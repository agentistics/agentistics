# A-features: capability matrix of mature coding harnesses vs Agentistics native harness

Scope: only what the fetched page text states. Products: CC = Claude Code, CX = Codex CLI/cloud, GM = Gemini CLI, OC = opencode, AMP = Amp, CP = GitHub Copilot CLI / cloud agent, CU = Cursor, CND = Conductor (a Gemini CLI extension). URLs are written without the leading https://. "Ours" is classified against INVENTORY.md (have / planned / partial / missing / never). Notes on source quality: several CC pages (tools-reference, permission-modes, skills, commands, statusline) were only partly captured in the input, so descriptions of those are limited to the visible text; Amp "handoff", "toolboxes", "thread-map" and "liberating-code-review" pages returned parse errors (only search summaries exist); Codex slash-command details were partly cut off in the source.

## 3. Top 15 gaps

1. Script-driven multi-agent runtime (Workflow-style: agent/pipeline/parallel/phase, schema outputs, deterministic replay, resume from saved results, caps of 16/4096/1000, plan-approval gate, live progress view, save as command) - giant.
2. Spec-driven plan mode proper: read-only tool whitelist, plan as an editable Markdown artifact, exit-with-approval tool, decision-complete question loop, phase-specific model - medium (on top of B4.7).
3. Spec/plan/track lifecycle with traceability (Conductor-style product/tech-stack/workflow files, per-track spec.md + plan.md, implement-with-checkoff, status, revert, review) tied to the ALM board - giant.
4. Schema-validated structured output with bounded retries for agent results and headless runs - small.
5. Native rendered-artifact tool (HTML/Markdown page, diagram, report, slide deck, chart) plus a "deliver this file with render" verb, kept local (D10) and surfaced in the Sessions workspace aside/Studio - medium.
6. Worktree isolation per agent plus a /batch-style decompose-approve-fan-out-per-unit-and-publish flow - medium.
7. Verification ladder: adversarial verifier agents, claim voting (deep-research pattern), stop-gates and no-progress detection, structured ReportFindings, per-check reviewer agents - medium.
8. Run-and-verify-the-real-app skills (/run, /verify, recorded launch recipe) as the POC-to-MVP truth check - medium.
9. /goal-style persisted autonomy with a token/credit budget, reminders and stop conditions (Codex rollout_budget, Copilot autopilot credits) - medium.
10. Project bootstrap (/init) plus instruction system upgrades: imports, path-scoped rules, just-in-time subtree files, personal local file - small.
11. Per-phase and per-stage model routing, a cheap small_model for side tasks, and an advisor/oracle second-opinion call - small.
12. Async and scheduled execution: cron/loop/wake-up tools, cloud or remote tasks, best-of-N attempts compared, issue-to-PR runners - giant (must be opt-in given local-first).
13. Persisted rewind and fork of conversation and code independently, export/import, per-message revert (beyond the in-memory checkpoint and H4/H21) - medium.
14. Inter-agent coordination: named-agent messaging, plan-approval handshake, forks that inherit the full conversation, resume finished subagents, adversarial peer debate - medium.
15. Context-cost controls for tools: deferred/searchable tool loading, per-agent MCP scoping, MCP resources and elicitation, skill cost view - small to medium.

Also worth noting but below the cut: network-domain allowlist proxy and OS sandboxes, shell environment scrubbing, dontAsk CI mode, prompt-render diagnostics (codex debug prompt-input), and mid-turn message queueing. No fetched product documents an explicit POC to MVP to product stage model or stage gates; the nearest are Conductor tracks, /batch, /goal and cloud issue-to-PR agents, so theme 3 would be new design work rather than a port.
