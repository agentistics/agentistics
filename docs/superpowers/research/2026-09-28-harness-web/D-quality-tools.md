## Notes worth keeping

- Claude Code's own docs keep a hard split between what a hosted product does (Code Review, ultrareview, Action) and what the local CLI does (/code-review, /security-review). A local-first harness realistically owns only the local column plus a headless mode that CI can call.
- Every reviewer above uses the same three-part shape: parallel finders, a verification pass that tries to refute candidates, and a ranked, deduplicated report with severity. Verification is the part that reduces noise (S6, S4).
- LSP is documented as inactive until a server is configured in Claude Code and off by default in opencode (S3, S10): both treat it as opt-in, which matches H25.
- Database, HTTP-client, package-manager and clipboard tools were not found as native tools in any fetched product; they are MCP or shell territory (S3, S11, S18).

## Top 10 gaps

1. Reviewer pipeline: parallel finder agents, a refutation/verification pass, dedupe and severity ranking, run locally on a diff (rows 1, 3, 4, 33). Medium once B6.1 subagents exist.
2. Structured findings tool (`report.findings` with file, summary, failure scenario, category) that the TUI/web render and mark fixed/skipped after the follow-up edit (row 2). Small.
3. LSP navigation tools beyond diagnostics: definition, references, symbols, implementations, call hierarchy, with rename as a stretch (rows 13-15). Medium.
4. Schedule/loop/monitor family: cron with expiry and jitter rules, self-paced wakeup with a stop flag, and a Monitor tool that pushes background output lines into the loop (rows 22-24). Medium, opt-in.
5. Review rules file plus severity/nit-cap/skip-path/verification-bar controls, separate from AGENTS.md (row 5). Small.
6. Structured test-runner tool returning per-test results, feeding after-edit steps and the review verifier (row 21). Medium.
7. Review-then-fix loop (`--fix`, autofix from findings) and PR comment posting through gh/glab (rows 6, 11). Small.
8. Headless CI mode for issue/@-mention to PR and CI-failure fixing, built on H16 plus git write tools (rows 9, 10). Giant; local-first constraint applies.
9. Semantic index: start with the ranked repo map (already B gap 13), add embeddings only with an explicit consent switch, given INVENTORY B6.6 (row 16). Giant.
10. Visual and rendered outputs: diagram/mermaid render, image generation, notebook cell editing (rows 17, 25, 26). Small each; image generation is provider-gated.

Deliberately low: desktop computer use (row 29) and deployment (row 27) clash with the sandbox and local-first constraints; DB and API-client tools (rows 18-19) are better left to the MCP bridge.
